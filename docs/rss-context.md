# 返信・引用の取得範囲

2026年9月12日に公開RSSを実測し、[公式仕様](https://docs.fxembed.com/guide/advanced/rss-atom-feeds/)と[フィード生成処理](https://github.com/FxEmbed/FxEmbed/blob/main/src/helpers/syndicationFeeds.ts)を確認した。

## 取得する内容

取得URLは `https://fxtwitter.com/thsottiaux/feed.xml?with_replies=true&count=100`。既定の `feed.xml` は返信を含めないため、公式の返信オプションを有効にする。

実測では100項目中、本人の投稿が61件、他人の投稿が39件だった。他人の項目は投稿URLの著者で除外し、単独では保存・通知しない。本人61件のうち36件は本文がメンションから始まり、返信とみられる。ただし、この数は返信全体の網羅性を保証するものではない。

| 情報 | 現在のFxTwitter RSS | 扱い |
|---|---|---|
| 本人本文・投稿ID・投稿日時 | 取得可能 | 既存の分類・重複防止に使用 |
| 引用元の投稿ID・著者・本文 | 明示的な引用ブロックから取得可能 | 本人本文と分離して保存・分類 |
| 引用本文の全量 | 最大280文字に省略 | 省略された部分は復元しない |
| 引用元の投稿日時 | 取得不可 | 保存済みの同一投稿があれば参照できる |
| 返信先の投稿ID・本文 | RSSに出力されない | 本人本文だけで判定。親本文は推定しない |
| 削除・非公開などの引用 | URLや本文が欠ける場合あり | 欠けた情報は利用できない |

引用元に予告がある場合でも、本人の短文・絵文字を確定予告として扱わない。通常の本文リンクや投稿順・時刻の近さは返信・引用の対応関係の根拠にしない。

## 返信の限界

本人の返信本文に `reset` があれば、親を取得できなくても通知対象になる。実測では `occasional reset`、`I reset usage twice`、`There is no schedule, only resets` を含む本人返信を取得できた。

一方、`👀` や時刻だけの返信で、親を読むまでReset関連と分からないものは、現在のFxTwitter RSSでは拾えない。RSS内に他人の投稿が隣接していても、それを返信先と推定しない。

将来、取得元が標準のAtom Threading `in-reply-to` を提供した場合は、明示された投稿IDから関連付ける処理を実装済み。同じ投稿IDの本文が保存されていれば参照できる。現在のFxTwitterでこの情報が取得できるという意味ではない。

新しいAPI・画像解析・HTMLページのスクレイピングは追加していない。返信オプションへの切替時に初めて見える既存投稿は追加baselineにし、過去返信をまとめて通知しない。
