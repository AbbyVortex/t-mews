# 通知方針（2026-09-12更新）

目的は、TiboのReset関連発言を早めに知らせ、リセット前に利用枠を使う時間を確保することです。取得後に確定情報を待ちません。通知するかどうかと、確定予告として表示するかどうかを別々に判定します。

## 通知と表示

| 表示 | 対象 |
|---|---|
| 💣リセット予告 | 本人が明示した実施予告・実施完了、Banked Resetの配布予告・配布報告。時刻は必須ではありません。 |
| 🍄注意報 | 本人の一般的なReset言及、ボタンの話、条件・否定・弱い匂わせ、確認できる返信先・引用元から関連する反応。 |
| 🍄注意報（延期／取消／時刻訂正・変更／実施否定） | 本人が表明した状態変更。新しい実施予告として表示しません。質問や推測の取消は取消の断定にしません。 |
| 📈 T-MEWS: 利用枠変更 | Resetに言及しない既存の明確な利用枠・消費率・制限ルール変更。 |

本人本文に `reset` があれば、活用・大小文字・一般的な前置きなどにかかわらず通知します。誤検知を許容する方針のため、Gitやキャッシュ等の技術的Resetも注意報です。単独のCodex/Astra名や、関連を確認できない絵文字だけの投稿は通知しません。明示的な🍄配布はResetの語がなくても通知します。

既存の内部分類名は維持します。`CANDIDATE` でも新方針では通知する場合があります。`Verdict.notify` が通知の要否、`display` が確定度、`change` が変更状態、`evidence` が本人の該当箇所です。保存用の分類名だけから通知要否を逆算しません。

本人本文と返信先・引用元を合成して確定予告を判定しません。関連元だけに予告がある反応は、本人のコメントが空・短文・長文のいずれでも注意報です。他人の投稿を単独で通知せず、識別できるリポストも従来どおり抑止します。

実装は [分類器](../src/classifier.ts)、[表示と配送](../src/pushover.ts)、[時刻解析](../src/reset-time.ts) に分かれています。判定はルール式で、AIや有料APIは使いません。

## 日本時間の予定・期限

投稿時刻と実施予定・期限を別項目で表示します。元の時刻表現を残し、明示された原文のタイムゾーン、または明示関連元にある同じResetのタイムゾーンを根拠に換算します。Tiboの居住地や普段の活動時刻から既定タイムゾーンを推測しません。

- 対応: `today` / `tomorrow`、`YYYY-MM-DD`、明確なAM/PMや24時間表記、noon、UTC/GMTと数値差、JST、PST/PDT、PT/Pacific Time/`America/Los_Angeles`。
- 相対日付は検知日時ではなく、本人の投稿日時を原文のタイムゾーンへ移して解釈します。PTは夏時間を反映し、切替時に存在しない時刻・二重になる時刻は未確定とします。
- PST/PDTは原文の明示的な固定オフセットとして扱います。PSTを勝手にPDTへ読み替えません。
- `by` / `before` / `until` は期限、`around` は頃、`after` はそれより後として保持します。`by midnight today` は期限ですが、midnightの日付境界や基準時区が曖昧なため未確定にします。
- 午前午後・日付・時区が不足する場合、morning等の幅のある表現、未対応の自然言語日付・時刻は「日本時間：未確定」。時刻解析に失敗しても通知は止めません。
- 本人の時刻だけの返信は、明示された同じResetの関連元から時区を補うことがあります。親の時計・日付を本人の新しい発言に置き換えません。親にしか予定時刻がなく本人が絵文字だけの場合、その予定の独立したJST換算には現在対応していません。
- 品質修正・ベンチマークなど別件の時刻はReset予定へ転用しません。解析できる文法には限りがあり、全ての自然な言い換えを保証するものではありません。

通知の長さ上限では、予定・期限のJST表示と本人の該当箇所を優先します。元投稿はPushoverのリンクボタンから開けます。

## 返信付きRSSへの切替と履歴

Actionsは `feed.xml?with_replies=true&count=100` を使います。[取得できる情報と実測上の限界](rss-context.md)を参照してください。現在のFxTwitterには返信先IDがないため、親を見ないと関連が分からない絵文字・時刻だけの返信は未対応です。引用元の明示IDと最大280字の本文は利用できます。

返信付きRSSへ初めて切り替えた正常取得で、初めて見えた項目を追加baselineにします。その後も切替時刻以前に公開された初見投稿はbaselineです。既存の投稿行・分類・送信台帳を再分類しません。切替後に公開された新規投稿から新方針で通知します。公開日時不明の遅着投稿は、切替前後を正確に区別できません。

追加の関係・確定度・根拠文は、既存 `events` テーブルの `post_analysis` イベントに保存します。新たなD1スキーマ移行は不要で、過去のsnapshotも読み込めます。既存の送信前永続化、単一投稿IDの重複防止、指定1投稿の復旧機能を維持します。同じ話題の別投稿は抑止しません。
